# Decision Record

> The project's key design decisions, written for a public reader. They were made by the project owner between 2026-10-09 and 2026-10-10. The detailed
> planning and tracking file (tasks, statuses, internal notes) is kept private; this file is the public summary. Evidence for every claim is in
> `docs/evidence/`. Identifiers such as `D2-09` (a task), `REQ-16` (a requirement) or `R-16` (a risk) that appear in other documents refer to
> entries in that private plan; their meaning is always stated next to them.

| ID | Decision | Choice | Rationale | Date |
| -- | -------- | ------ | --------- | ---- |
| DEC-01 | Dataset | Four Kaggle datasets by `caesarmario` with daily, weekly and monthly prices for **BBCA, BBNI, BMRI, BBRI** (Indonesia Stock Exchange), 2019-01-01 → 2026-10-08 in the snapshot used | One ticker allowed no comparison; four large Indonesian banks with identical schemas and identical trading dates enable comparative analysis without extra source complexity (`docs/DATASET.md`) | 2026-10-09 |
| DEC-02 | Business domain | Financial market analytics: **Indonesian banking stock performance**, for an individual investment analyst; descriptive and historical, not investment advice | Supported by the available fields (prices and volume per ticker and day); no fundamentals are available | 2026-10-09 |
| DEC-03 | Business questions and KPIs | Questions Q1–Q5 and KPIs K1–K11 (`docs/KPI_DEFINITIONS.md`): `adjclose` total-return basis, simple returns, base date = first day on which all four tickers traded, volume-status flags, 60-session volatility × √252, drawdown, monthly/yearly returns with a partial flag, relative volume | `adjclose` makes banks with different dividend policies comparable; flagged zero-volume rows get NULL returns instead of an artificial 0% | 2026-10-09 |
| DEC-04 | Processing strategy | **Batch** (manually triggered or scheduled Databricks Job); streaming is a possible future extension | The source is a periodic full snapshot (published daily, full history re-extracted each time), and historical analysis needs no low latency | 2026-10-09 |
| DEC-05 | Implementation tooling | Notebooks (Databricks source-format `.py`) + Lakeflow Jobs + custom data-quality checks writing to `ops` tables; PySpark with Spark SQL where clearer; no extra libraries; land the 4 daily CSVs + 4 `run-summary.json` | Hand-written checks give direct control over audit rows, quarantine and blocking; declarative pipelines were considered but add abstraction a small full-refresh batch does not need; CSV avoids an untested Parquet nanosecond-timestamp read | 2026-10-09 |
| DEC-06 | Load strategy | **Full refresh**: deterministic overwrite of Bronze, Silver and Gold from the landed snapshot; `ops` tables append-only | Each source version rewrites the full history (adjusted prices change retroactively), so appending would mix inconsistent histories; 4 × 1,887 rows make overwrite cheap and idempotent | 2026-10-09 |
| DEC-07 | Workspace and storage | Databricks **Free Edition**, serverless only; catalog `workspace`, schemas `bronze`, `silver`, `gold`, `ops`; Unity Catalog Volume `workspace.bronze.landing`; no secret scope (no credentials) | Capabilities verified in a manual check (`docs/evidence/d1-02-workspace-capabilities.md`) | 2026-10-09 |
| DEC-08 | Gold data model | One dimension + four facts, each at one grain: `dim_ticker`, `fact_daily_metrics`, `fact_monthly_metrics`, `fact_yearly_metrics`, `ticker_summary`; lineage columns on every table; no partitioning | Dashboard queries stay thin single-table selects; each KPI lives in exactly one place, which keeps reconciliation simple (`docs/DATA_MODEL.md`) | 2026-10-09 |
| DEC-09 | Code management | Develop locally, push to a public GitHub repository, run notebooks from a Databricks **Git folder** | A public repository needs no credentials in Databricks; verified with a Git folder clone | 2026-10-09 |
| DEC-10 | Testing approach | Tests run on the same serverless runtime as the pipeline (Spark unit-test notebook) plus plain-Python tests locally; data-quality checks per layer; rerun and induced-failure tests; independent reconciliation queries (`docs/TEST_STRATEGY.md`) | No local Spark is needed, and no access token for remote execution | 2026-10-09 |
| DEC-11 | Layering | **Bronze → Silver → Gold** (medallion), mandatory | Clear separation of raw, validated and business-ready data (`docs/ARCHITECTURE.md`) | 2026-10-09 |
| DEC-12 | Public repository content | Publish code, docs and evidence; keep raw data, credentials, local planning files, AI-assistant configuration and third-party reference docs out of the repository (`.gitignore`) | The upstream data terms are unverified, so raw data is not redistributed; planning notes are private working material | 2026-10-09 |
| DEC-13 | Induced-failure test | Replace one data row with a copy of the previous row (the row count stays the same), so Bronze passes and the Silver duplicate-key check must stop the run | An *added* row would be stopped earlier by the Bronze row-count check; this variant tests the Silver blocking path (`docs/evidence/d2-09-failure-test.md`) | 2026-10-10 |
| DEC-14 | K7 peak date rule | `peak_date` = earliest date (≤ trough) whose `adjclose` equals the running peak at the trough, i.e. **the day the peak was set** | The earlier rule (latest date with drawdown = 0) reported a non-trading holiday row (BBNI 2019-04-19); verified after the rebuild: every peak date is a normal trading day (`docs/evidence/d2-05-gold.md`) | 2026-10-10 |
| DEC-15 | Code licence | **MIT** (`LICENSE`) for the code; the market data is not included or redistributed and stays subject to its source's terms | Permissive licence for a public portfolio project; the upstream data terms are unverified (`docs/DATASET.md`) | 2026-10-10 |
| DEC-16 | Dashboard export | Commit `dashboards/indonesian_bank_stocks.lvdash.json` unedited | It documents the built dashboard exactly; the Databricks object IDs it contains (dashboard and dataset IDs) are not credentials; whether an import assigns new IDs is unverified | 2026-10-10 |
